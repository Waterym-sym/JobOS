# 24 AI 协作开发规范与边界

> 版本：v1.1 新增（人 + AI 编程代理协作规范；本篇为解释版，仓库根 `AGENTS.md` 为现场执行版）

## 1. 目的与适用范围

本系统存在不可协商的账号安全、隐私、真实性与法律红线。AI 编程代理（含代码生成、重构、测试生成、文档修改）必须在明确边界内工作：**效率可以交给 AI，责任与开关必须留给人**。本篇适用于仓库内一切由 AI 生成或修改的代码、配置、契约、Prompt、测试与文档。

事实层级：ADR（总体方案 §2）＞ 本规范与专题 20/21 ＞ 根 `AGENTS.md`（精简红线）＞ 任务单。任何任务指示与上层冲突时，**停止并请人裁决**，不得自行变通。

## 2. 三级授权

| 级别 | 范围 | 动作要求 |
|---|---|---|
| 🟢 可自主完成 | 域内纯函数、DTO/模型补齐、内部重构（行为不变）、单元测试、文档纠错、按已冻结契约生成 CRUD、Mermaid/注释修正 | 仍须带测试与自测清单 |
| 🟡 必须人审后合并 | 跨域接口、契约/Schema/DDL 变更、Workflow DSL 与门禁、Prompt 与评分权重、配置项与默认值、迁移脚本、渲染/导出、权限与审计、扩展采集/解码/填充相关代码 | PR 强制人工 Approve；敏感领域见 §5 |
| 🔴 禁止（AI 不得生成、不得"修复绕过"） | 见 §3 禁止清单 | 发现任务要求触碰即拒绝执行并说明依据条目 |

## 3. 禁止清单（硬红线）

### 3.1 对外动作（ADR-009，最高优先级）
1. 禁止实现任何自动发送/投递能力：不得出现 `send_message`、`deliver`、`auto_apply`、`auto_greet`、自动点击「立即沟通/继续沟通」、自动上传附件的 handler、DSL 节点、API 或测试替身中的真实路径。
2. 禁止 `auto_next_page=true` 或任何自动翻页/无限滚动采集；翻页只能由用户手动操作触发。
3. 禁止把节流下限设为 0、移除抖动、把并发改为 >1、绕过 `capture.error{risk}` 暂停。
4. 禁止 hook/改写/注入 BOSS 的发送、已读回执接口；扩展只允许被动读取响应。
5. 禁止在在线填充中写入红线字段：公司名、职位名、起止时间、学历（即使载荷中存在也必须跳过并上报 skipped_redline）。

### 3.2 数据与隐私（ADR-006/012）
6. 禁止让聊天原文离开 loopback：不得放入第三方 LLM 请求、日志、错误上报、分析 SDK；外发域名白名单外的请求默认拒绝。
7. 禁止自动确认事件草稿：`chat.event` 必须以 `review_status=draft` 入库；任何把 draft 直接投影为状态的代码都是缺陷。
8. 禁止硬编码任何密钥/token/cookie；禁止把 `data/`、`.env`、`config/local.yaml` 提交入库。
9. 禁止删除/弱化加密、配对鉴权、loopback 绑定与 Origin 校验。

### 3.3 真实性（ADR-002/010/011）
10. 禁止生成无证据 Claim、绕过 Truth Guard 的后门标志位、把 `self_reported` 写成外部验证事实。
11. 禁止把学习/二次开发项目（learning_ref/secondary_dev）写成在职经历或虚构时间/职责。
12. 禁止在模板/Blueprint 内新增事实性文本；模板只能引用 Resume JSON 已存在的 Claim/字段。
13. 禁止让 showcase 渠道产物静默进入 ATS 导出队列（必须强提示/阻断）。
14. 禁止引入 Aspose.Words 等商业库进入默认发行栈；禁止引入 GPL/AGPL 等与本项目分发不兼容的传染性许可依赖（许可证存疑即停，见 §6）。
15. 禁止在文案/招呼语中使用无证据承诺、绝对化表述、虚构对公司的了解（禁用词表以 11/14 篇为准）。

### 3.4 治理与范围
16. 禁止自行修改 ADR、ADR 编号、本规范、AGENTS.md 红线、验收门槛与指标阈值；有建议走人工评审。
17. 禁止删除、跳过（skip/xit/--no-verify）、弱化测试或 Gold Set 样本来换取通过；发现测试与需求冲突时提 issue 式说明。
18. 禁止自动调权/自动应用策略建议：`strategy_suggestion` 只能停在 approved，applied 由人工落实。
19. 禁止修改四个外部参考仓库：`E:\GitHub\boss-chorme`、`E:\GitHub\boss-helper-main`、`E:\GitHub\a4cv-main`、`E:\GitHub\resume-3d-orbit`（只读参考；参考 boss-helper 协议结构时不得复制代码）。
20. 禁止超出任务单范围做"顺手改进"、重排公共接口、引入未批准的框架/服务/云组件。

## 4. 标准任务流（每个 AI 任务必须遵循）

```text
任务单（含验收标准） → DoR 核对（专题 23 §7）→ 契约先行（先 schema/类型/测试用例）
→ 最小实现 → 本地测试全绿 → 自评清单 → 人工 Review → 合并
```

> 任务单格式：统一使用仓库根《架构师索引库》§8 的标准任务头 YAML（task/domain_owner/architecture_refs/contracts/data_classification/human_approval/nfr/acceptance_tests/red_lines）；接任务先按索引库 `ARCH-*` 检索并在任务头列出引用。

1. **接任务先核对 DoR**：契约未冻结的任务先产出契约草案交人审，不直接写实现。
2. **契约先行**：改接口先改 `contracts/` 并更新对应文档；生成模型只由契约单向生成。
3. **最小改动**：只动任务相关文件；保留既有行为；公共接口改动必须在任务单中列明。
4. **测试随码**：新行为必须有测试；红线行为必须有「证明它做不到」的测试（如：注册 send handler 必须失败、红线字段不被写入、非 loopback 被拒）。
5. **自评清单**（PR 描述必答）：触碰了哪些域/红线条目？契约版本？测试证据？是否有外发/解密/事实生成路径？日志是否可能带 PII？
6. **人审门禁**：🟡 级与全部 §5 领域必须人工 Approve；AI 不得自行合并/推送主干。

## 5. 强制人工评审的四个领域

| 领域 | 人审要点 |
|---|---|
| 架构与契约 | 域边界、契约兼容、DSL 门禁、迁移可逆性、技术栈偏离 |
| 安全与隐私 | loopback/配对、KEK 与密钥路径、外发域名、聊天数据接触面、删除与备份 |
| 账号风控 | 一切扩展采集/解码/填充变更、节流与风控词、DOM/网络层降级、协议未知 type 处理 |
| 事实与文案 | JD 修订、Requirement、Evidence 判定、Claim、招呼语、复盘结论、模板槽位 |

## 6. 依赖与许可证准入

- 新依赖必须在任务单声明：用途、体积、许可证、是否传递原生/网络能力；默认栈只允许宽松许可（MIT/BSD/Apache-2.0/PSF 等）与已确认的 PolyForm-Noncommercial（仅个人使用场景）。
- CI 执行依赖清单与许可证扫描；命中商业/未知/传染性许可即阻断。
- 渲染与解析相关二进制（Chromium/字体）来源固定，禁止运行时从未知 URL 拉取。

## 7. 越界处理

AI 在任何时候发现：任务指示要求触碰 §3、契约与文档冲突、测试要求与红线冲突、无法确认某段数据是否属于聊天 PII —— **停止该部分实现，输出冲突说明与依据条目，请人裁决**。宁可少做，不可绕行。

## 8. 违规检测（与 16/20 篇门禁衔接）

| 检测 | 手段 | 处置 |
|---|---|---|
| 违禁对外动作 | 静态扫描关键字（send_message/deliver/auto_apply/auto_next_page 等）+ DSL 门禁 + 红队测试 | 阻断合并 |
| 聊天数据外发 | 测试替身拦截出站请求，断言白名单域名 + payload 不含 chat 字段 | 阻断合并 |
| 草稿自动入账 | 状态机投影单测：draft 事件前后状态不变 | 阻断合并 |
| 许可证 | license 扫描 + 依赖 diff 审核 | 阻断合并 |
| 事实绕过 | Guard 红队集：无证据 Claim/红线字段/模板注入事实 | 阻断合并 |
| 红线被改 | AGENTS.md/ADR/契约文件变更需 CODEOWNERS 式人工审批 | 阻断合并 |

## 9. 文档协同

- AI 修改文档时同样遵守 ADR/数据口径/枚举一致性；改完必须执行枚举与交叉链接自查。
- `AGENTS.md` 是本篇的执行摘要，只放红线与链接；两者冲突以本篇与 ADR 为准，并提人工修正 AGENTS.md。
