# 19 项目实施计划

> 版本：v1.1（个人/小团队，按依赖与出口门禁推进，无日历排期；阶段 P0–P6）

## 阶段计划

| 阶段 | 范围 | 出口门禁（DoD） |
|---|---|---|
| **P0 文档与契约** | v1.1 文档体系（总体+22 篇）、WS 协议契约（信封/命令/事件/数据契约）、数据契约、筛选规则目录 | 评审通过；协议契约可被扩展与服务端同时引用；Gold Set v0 与规则边界集 v0 |
| **P1 本地骨架 + 扩展重写** | Compose（api/pg/redis/worker/web）、配对鉴权、WS Gateway；扩展移除 MySQL8789 与 TS 评分核心，采集改走 8788；老 MySQL 一次性迁移 | 扩展列表/详情采集入 PG 且幂等；8789 链路删除；loopback 审计通过；迁移抽样对账一致 |
| **P2 采集+筛选+JD/匹配** | 岗位池、Filter Set 与 Stage-0 规则引擎（薪资/活跃度/否定语境/去重/通勤可选）、捞回；JD Intelligence 批量解析；Stage-1 匹配 + ATS 投递建议 | 真实采集样本：每条淘汰可解释、漏斗计数可对账；F1/薪资解析达标；候选区可确认 |
| **P3 模板系统** | 正交模型与内置精选 ATS/Showcase 模板；DOCX 开源导入管线（Blueprint/分级/批量/失败报告）；网格库（3D 画廊默认关闭）；A4 编辑器；PDF/PNG/HTML/DOCX/MD 导出与回读校验 | 槽位映射回归集全绿；ATS 模板解析率 ≥98%；C 级降级明示；渠道隔离断言通过 |
| **P4 三形态简历+招呼语+在线填充** | 投递包编排、Claim 三渠道渲染、Greeting A/B、Truth Guard 扩展（话术/载荷/模板一致性）、ATS 在线检查、扩展四模块填充与 `copy_greeting`、人工发送回执 | 已使用 Claim/话术溯源 100%；红队确认无自动发送路径；填充红线字段零写入 |
| **P5 聊天回采+事件** | 扩展网络层解码（proto 结构）+ DOM 降级；chat.event 草稿；事件确认台；状态机投影 | 约面/拒绝分类准确率达标；草稿不自动入账；解码降级链路可用 |
| **P6 复盘+漏斗+策略** | 单岗复盘、阶段汇总、漏斗仪表盘、Strategy Suggestion 生命周期；策略人工审核 | 全漏斗真实跑通且数字可对账；approved 建议不触发任何自动参数变更；备份恢复演练通过 |

## 依赖关系

```text
P0 ─→ P1 ─→ P2 ─→ P4 ─→ P5 ─→ P6
              │       ↑
              └→ P3 ──┘   （P3 模板系统只依赖数据/简历契约，可与 P2 后半并行）
```

关键前置：Candidate/Artifact/Evidence 数据契约（P1 内随骨架完成）先于 Match/Resume；`E:\Profile\work` 连接器与 career-kb/旧简历导入放在 P1 末–P2 初，保证 P2 有真实知识库可用；冷启动四类导入的确认 UI 不晚于 P2 出口。

## 工作包与 Owner 制

|---|---|
| 协议/数据契约 | WS 信封/命令/事件、raw_job/screen/event/template 表与迁移、契约测试 |

| 复盘/漏斗/策略 | 复盘 Prompt、看板、建议生命周期、对账工具 |

## 节奏与变更治理

个人/小团队按 Sprint 推进，每 Sprint 末演示**真实数据闭环**（不用 mock 录屏收尾）。涉及数据范围、对外动作、模型供应商、PII、模板版权、自动决策的变更必须更新 ADR/风险登记。每阶段以量化门禁决定是否继续；不满足门禁则缩范围，不标完成。

## 延后项

其他招聘渠道（仅留 source 字段）、3D 画廊默认开启、在线协同/Coach、自动调权、图数据库、可视化工作流编辑器、Aspose 商业引擎、自动投递（永久禁止，非延后）。
