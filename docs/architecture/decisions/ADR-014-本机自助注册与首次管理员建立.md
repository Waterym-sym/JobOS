# ADR-014：本机自助注册与首次管理员建立（待独立评审）

- Status: proposed — 未获独立评审，禁止据此修改认证实现或开放公网
- Date: 2026-09-18
- Amends: ADR-013 第 2 项的邀请注册及服务器命令引导首个管理员；其余隔离、会话、隐私、迁移和发布门禁不变
- Related: `ARCH-SEC-003`、`ARCH-DATA-001`、`ARCH-API-001`、`ARCH-CONTRACT-001`、P1-007

## Context

本人反馈现有“迁移、服务器创建管理员、邀请码、登录”步骤过于繁琐，希望网页注册后直接使用邮箱和密码登录。当前本机数据库仍在 0004，已有旧单用户数据；不能让任意新账号无审计地认领这些数据。邮箱服务未接入，注册邮箱无法证明所有权；本期仍不部署公网。

## Proposed decision

1. 本机部署允许邮箱、密码及业务角色（求职者／招聘者）自助注册，不再要求邀请码；注册成功即建立服务端会话。密码长度、哈希、Cookie、CSRF、Origin、限流与会话撤销要求不降低。
2. 仅在尚无任何账号、Web 与 API 均处于 loopback 本机模式且数据库已升级到 0005 时，首次**求职者**注册可原子地成为管理员，并在同一事务中认领旧单用户私有行。并发首次注册必须串行化，失败不得留下半完成归属。招聘者不能成为首个管理员；网页必须清楚告知首次注册会认领旧数据。
3. 后续自助注册的账号均无管理员权限，不能读取首个账号的旧数据。求职者现有流程在所有权查询、缓存和后台任务完成隔离前仍不可对普通账号开放；招聘者保持独立空工作台。
4. 未验证邮箱不得被描述为已验证身份；密码恢复暂沿用管理员签发单次凭据。若未来要开放公网，需另行评审邮箱验证、共享限流、滥用防护及部署密钥；本 ADR 不授权公网部署，也不解除 `PUBLIC_MODE` 的强制关闭。
5. 数据库迁移仍是一次性运维步骤，不在普通 Web 请求或 API 启动时自动执行。可由维护者在备份后代为执行，但不能将失败迁移隐藏在“注册”按钮后。

## Independent review questions

- 本机首次注册认领旧数据的身份证明与抢注风险是否可接受？是否改为本机一次性安装码？
- 现有数据归属、失败回滚和双并发首次注册是否有可复现负例？
- 无邮箱验证情况下的重置与账号滥用边界是否清晰？
- 本次修改是否仍满足 ADR-013 的公网目标，或需要把公开注册另列 Go/No-Go？

独立评审通过前，仅保留提案，不修改已接受的 ADR-013、机器契约或认证代码。
