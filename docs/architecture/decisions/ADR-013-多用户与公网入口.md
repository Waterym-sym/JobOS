# ADR-013：多用户身份隔离与公网 Web 入口

- Status: accepted for implementation（2026-09-18 本人报告 ADR-013 独立评审通过；未授权公网部署，代码验收仍待人审）
- Date: 2026-09-18
- Supersedes: ADR-005 中「唯一人类用户、所有入口仅 loopback、无用户体系」的适用范围；不改变 ADR-005 的扩展唯一采集端及 ADR-006/009 的隐私、人工发送红线
- Related: `ARCH-SEC-001`、`ARCH-SEC-003`、`ARCH-DATA-001`、`ARCH-API-001`、`ARCH-CONTRACT-001`、`ARCH-EXT-001`

## Context

现有系统以本机单用户 PIN、Web 代理统一注入配对令牌和不带 owner 的岗位表实现，不能直接服务公网多个用户。来源项目的登录只存浏览器 `localStorage`，上传与注销是模拟行为，也不能作为认证或个人数据处理机制。本人已裁决目标为公网多用户，同时本期只交付代码与本地验收，不实际部署公网。

## Decision

1. **网络边界**：仅 Web/TLS 边缘入口可面向公网；API、扩展 WS、PostgreSQL、Redis、Worker、管理接口均不直接公开。现有 BOSS 扩展与聊天回采继续走独立本机链路，不接入远程账号。公网模式禁用本机采集入口；聊天原文不上传至公网服务。
2. **身份**：邮箱+密码、管理员一次性邀请码注册；账号业务角色为 `seeker` 或 `recruiter`，治理管理员为独立权限位。部署者在服务器命令行引导首个管理员，网页不得抢注管理员。招聘者本期只具备独立账号、资料和空工作台，无求职数据权限或招聘业务能力。
3. **会话与恢复**：服务端存储密码哈希和会话，浏览器持有 `Secure`、`HttpOnly`、`SameSite` Cookie；写请求校验 CSRF 和 Origin，登录/邀请/重置限流并留不含秘密的审计。管理员签发短时单次密码重置凭据，使用后撤销旧会话。浏览器不再获得或借用扩展配对令牌；管理员治理权限不默认包含查看其它账号私人简历/岗位的权限。
4. **所有权**：服务端从已认证主体确定 owner，不信任请求、文件名或队列消息中未经校验的 owner。个人行、缓存、文件、后台任务和幂等键全部按用户隔离；持久表采用 owner 外键与查询过滤，并以 PostgreSQL RLS 为第二道防线。正常请求角色不得拥有 `BYPASSRLS` 或超级用户权限，迁移连接与运行连接分离；连接池复用后不得继承前一用户上下文。共享的招聘平台来源目录需显式标为共享。旧本机数据经备份与审计后归属服务器命令引导的首个管理员。
5. **资料与删除**：PDF/DOCX 仅写入账号私有存储；原件上传不等于解析成功。无简历入门从空白字段开始；示例个人资料不入库。注销须撤销会话并删除该账号私有数据；最后一名管理员需先移交权限，禁止直接注销。聊天原文仍仅本机处理。
6. **迁移与发布**：新增 Alembic 迁移必须实现 downgrade 并在隔离库往返验证；降级无法安全收敛多用户数据时显式拒绝，不能静默混合或丢弃。架构/权限方案独立人审后才可进入实现；本地功能验收不能替代公网安全与运维 Go/No-Go。

## Consequences / Review gates

- 现有浏览器 PIN 与 Web 代理共享配对令牌必须替换；涉及 API、数据层、Worker、扩展部署边界和 UI，不能只复制页面。
- 需要新的身份/所有权机器契约、跨账号负例、数据迁移/回滚演练、文件与缓存隔离、截图回归及账号删除对账。
- 既有自动外发禁止、采集风控、Truth Guard、聊天不出本机和人工评审阈值继续有效；对外服务还需另行审查 TLS、备份、限流、会话与日志。
- 本人于 2026-09-18 报告独立评审通过，允许进入契约与实现；现有单用户实现和 loopback 绑定在代码验收前仍不得放宽。公网部署须另行 Go/No-Go。
