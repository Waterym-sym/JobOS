# 23 开发基线与契约固化

> 版本：v1.1 新增（开发就绪基线：仓库结构、技术栈版本、配置清单、契约真源、各阶段 Definition of Ready）

## 1. 目标

把「技术方案级」文档接到「可以实际开工」：规定代码仓库结构、技术栈版本、配置与密钥、本地开发/测试规程，并把跨端协议固化到 `contracts/` 机器可读文件，使扩展与服务端可并行开发、契约可自动测试。本篇不包含业务代码。

## 2. Monorepo 目标结构

```text
AI_Resume_OS/
├─ AGENTS.md                     # AI 编程代理现场硬红线（见专题 24）
├─ contracts/                    # 机器可读契约真源（v0-draft → P0 冻结）
│  ├─ ws/                        # 扩展 WebSocket 信封/命令/事件/数据 JSON Schema
│  ├─ api/openapi.yaml           # REST OpenAPI 3.1 骨架
│  ├─ db/0001_baseline.skeleton.sql
│  ├─ dsl/workflow.schema.json
│  └─ filters/filter-set.schema.json
├─ apps/
│  ├─ extension/                 # MV3 浏览器扩展（TypeScript + Vite）
│  └─ web/                       # 本地控制台（React 18 + Vite + TS）
├─ services/
│  ├─ api/                       # FastAPI 进程（内部包结构见下，对齐总体 §4.3）
│  │  ├─ app/                    # HTTP/BFF、DTO、SSE、WS Gateway(8788)、本地配对鉴权
│  │  ├─ domains/                # capture/screening/job/candidate/evidence/matching/
│  │  │                          # resume/template/application/retrospective（域内聚合+端口）
│  │  └─ platform/               # workflow、ai、shared（ORM/事件/审计/配置/错误码/本地密钥）
│  ├─ worker/                    # 异步任务：AI 节点、JD/匹配/简历/招呼语/复盘
│  └─ worker-renderer/           # 文件解析、DOCX 批量导入、Chromium/WeasyPrint/python-docx + 中文字体
├─ packages/
│  ├─ contracts-py/              # 由 contracts/ws 生成的 Pydantic 模型（单向生成）
│  └─ contracts-ts/              # 由 contracts/ws 生成的 TS 类型（单向生成）
├─ migrations/                   # Alembic 迁移（P1 起为数据库唯一变更入口）
├─ data/                         # bind mount：files/ templates/ chat-raw/ backups/（gitignore）
├─ config/                       # 本地配置模板（.env.example，不含真实密钥）
├─ tests/                        # 契约测试、Gold Set、红队集、E2E
├─ docker-compose.yml
└─ docs/
```

约束：域模块边界遵循专题 02（Capture/Screening/…/Platform），跨域只经 Application Service 或领域事件；扩展侧不允许出现评分/生成业务核心（专题 21 已明确删除项）。

## 3. 技术栈与版本基线

| 层 | 选型 | 版本基线（P0 锁定 minor） |
|---|---|---|
| API/BFF | Python + FastAPI + Pydantic v2 + Uvicorn | Python 3.12、FastAPI 0.11x、Pydantic 2.x |
| ORM/迁移 | SQLAlchemy 2.x（mypy 严格模式）、Alembic | 2.0 / 1.1x |
| 数据库 | PostgreSQL + pgvector | PG 16、pgvector 0.7+ |
| 队列/缓存 | Redis（队列 + 缓存，不作真源） | Redis 7 |
| Worker | Celery 或 ARQ（P0 二选一记录 ADR） | 随 Python 3.12 |
| Web 控制台 | React 18 + Vite + TypeScript 5 + TanStack Query | Node 20 LTS、pnpm 9 |
| 浏览器扩展 | Manifest V3 + TypeScript + Vite（service worker） | 同上 Node 基线 |
| 渲染 | 无头 Chromium（HTML→PDF/PNG）、WeasyPrint、python-docx | 镜像内固定版本 + 中文字体（思源/Noto CJK） |
| DOCX 解析 | openxml 直读 + python-docx（开源，ADR-011） | 禁止 Aspose 进入默认栈 |
| 向量/检索 | pgvector HNSW + PG 全文 GIN（中文分词） | 随 PG16 |
| 测试 | pytest + httpx + schemathesis；Vitest + Playwright | 最新稳定 minor |
| 代码质量 | ruff + black + mypy；eslint + tsc --noEmit + prettier | 配置入库 |

版本升级策略：minor 升级允许，major 升级需 ADR；镜像 digest 锁定，`compose` 配置版本在「关于」页展示（专题 17）。

## 4. 配置与密钥清单

配置分层：`config/defaults.yaml`（非密默认值）→ `config/local.yaml`（本机覆盖，gitignore）→ 环境变量（密文）。所有可配项必须在 `.env.example` 与控制台「设置」页可见；带下限的参数不允许配到下限以下。

| 键 | 默认 | 约束 | 密文 |
|---|---|---|---|
| `HOST_BIND` | `127.0.0.1` | 禁止 0.0.0.0/公网网卡 | 否 |
| `API_PORT` | `8000` | — | 否 |
| `WS_PORT` | `8788` | 扩展唯一接入 | 否 |
| `PAIRING_TOKEN` | 首启随机生成 | 仅存本机配置目录，不进镜像/仓库 | 是 |
| `CHAT_KEK_FILE` | `config/chat_kek.key` | 本机随机 256bit，权限 600，不入库不入镜像 | 是 |
| `LLM_PROVIDER / LLM_API_KEY / LLM_BASE_URL` | 空（必须显式配置） | Key 只出本机；标注不训练供应商 | 是 |
| `EMBEDDING_PROVIDER / KEY` | 可指向本地 embedding | S3/S4 内容默认不外发（专题 06/07） | 是 |
| `CAPTURE_MIN_DELAY_MS` | `1800` | **硬下限 1800，禁止配 0**；抖动 ±20% | 否 |
| `CAPTURE_CONCURRENCY` | `1` | 恒 1，不开放调高入口 | 否 |
| `DETAIL_LIMIT_PER_BATCH` | `30` | 可调正整数 | 否 |
| `AMAP_API_KEY` | 空 | 不配置则通勤规则 skip | 是 |
| `STORAGE_DIR` | `./data` | files/templates/chat-raw/backups 分层 | 否 |
| `BACKUP_CRON` | 每日 pg_dump | 保留份数本机可配 | 否 |
| `CHAT_TO_THIRD_PARTY` | `false` | 默认关；开启需二次确认 + 脱敏管线 | 否 |

## 5. 本地开发与测试规程

启动顺序：`cp config/.env.example .env` → `docker compose up -d pg redis` → `alembic upgrade head` → 启动 `services/api`（含 WS Gateway）与 `services/worker` → `pnpm dev` 起 web → 扩展「未打包加载」apps/extension/dist → 控制台「扩展接入」完成配对（专题 17）。

- 热重载：api/worker uvicorn `--reload`；web/扩展 Vite HMR；渲染器改动走镜像重建。
- 数据：本地开发库与运行库分离；提供 `make seed-sample`（脱敏样本，不用真实聊天原文）。
- 测试：`pytest`（单测 + 契约测试 schemathesis 对 openapi.yaml、WS 协议双端一致性）；`pnpm test`（Vitest）；Playwright E2E 使用专题 16 的关键用例；Gold Set/红队集/规则边界集入 `tests/fixtures`，禁止使用真实账号。
- 生成代码：`packages/contracts-py|ts` 只由 contracts/ 单向生成，手改会被 CI 覆盖。

## 6. 契约真源与固化流程

| 契约 | 机器真源 | 语义真源 | 冻结时点 |
|---|---|---|---|
| WS 信封/命令/事件/岗位与聊天数据 | `contracts/ws/*.schema.json` | 专题 21 | P0 |
| REST 接口 | `contracts/api/openapi.yaml` | 专题 13 | P0 骨架；每阶段补该阶段路径 |
| 数据库 | Alembic 迁移（P1 起）；`contracts/db/0001_baseline.skeleton.sql` 仅为 P0/P1 对账草案 | 专题 12 | P1 首个迁移冻结 |
| Workflow DSL | `contracts/dsl/workflow.schema.json` | 专题 15 | P2（首个真实流程上线前） |
| Filter 规则 | `contracts/filters/filter-set.schema.json` | 专题 08 | P2 |

规则：

1. 文档定义语义与红线，contracts 定义形状；两者冲突时**先改文档评审，再改契约**，禁止反向。
2. contracts 当前全部为 `x-status: v0-draft`，P0 评审后转 `v1`；变更走 PR + 契约测试 + 版本号协商（WS 信封 `v:1`，未知 `type` 必须显式拒绝/忽略并记录，不得崩溃）。
3. 契约测试：双端各跑同一组 JSON Schema 用例；CI 做 OpenAPI schema 兼容 diff（只允许加字段）。
4. 协议中不存在、也永不注册 `send/deliver/auto_next_page/auto_upload` 类命令；契约测试与静态扫描双保险（专题 16/21/24）。

## 8. 横切规范

- **可观测**：每个请求/命令带 `trace_id`（WS 信封 `id` 即追踪 ID 之一）；日志结构化 JSON，禁打聊天原文与密钥；审计事件见专题 18。
- **幂等**：写请求 `Idempotency-Key`；WS 上报按 `source+ext_id` / `ext_msg_id` 幂等；事件 at-least-once 投递，消费端去重。
- **时间**：全系统 UTC 存储、ISO-8601；展示层转本地时区。
- **错误**：统一信封 `{code,message,trace_id,details}`，错误码→HTTP 映射以专题 13 为准。
- **提交**：Conventional Commits；一个任务一个分支；PR 描述必须关联任务单与契约版本；AI 生成代码按专题 24 标注并附测试。
