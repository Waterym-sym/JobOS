## 1. 这个前端是什么（先钉死主语）

- **具体主语**：一套只在本机打开的「求职作战室」——不是招聘网站，不是 SaaS 后台，不是仪表盘玩具。使用者只有一个人：你本人。
- **受众**：懂技术的全栈从业者（你），长时间盯着 JD、简历、聊天记录做判断，不需要引导式 onboarding，不需要营销页，不需要多账号入口。
- **唯一任务**：让「采集 → 筛选 → 候选 → 投递包 → 人工触达 → 回采确认 → 复盘」这条链路上的**每一次人工判断又快又稳**，并且让「AI 说了什么 / 证据在哪 / 哪些还没确认」永远一眼可辨。

所以 UI 的气质不是「酷炫 AI 产品」，而是**编辑案头 + 调度终端**：安静、密集、可扫读，颜色只在「需要你行动」和「证据状态」上出现。

## 2. 五条设计原则

1. **内容是主角，chrome 退后**：最大面积给 JD 原文、简历、聊天；导航和工具栏压到最小，无装饰插画、无渐变英雄区。
2. **导航即漏斗**：左侧导航不是功能菜单，而是主流程七级管线，每级带实时待办计数——你随时知道「现在该处理什么」。
3. **AI 与本人有明确的视觉阶层**：AI 产出永远「草稿态」呈现（虚线边、模型标签、证据点），经你确认后才「转正」（实线、正常卡片）。**UI 不允许让 AI 内容看起来已被认可**。
4. **危险与外发动作有形状**：所有会触达外部的动作（填充预览、复制招呼语、标记已发送）有统一的动作区与措辞；界面里**物理上不存在**「自动发送 / 一键投递」按钮。
5. **每个数字都能点下去对账**：漏斗数字、评分、淘汰原因、证据计数——点得开来源，看不到来源的数字不显示。

## 3. 设计语言（Design Tokens）

### 3.1 隐喻：案头与印章

岗位是案卷，证据是档案，AI 是实习编辑（草稿交你签发），招呼语是待寄的信。唯一的「重色」来自**印章朱**——只盖在「需要本人拍板」的地方。整体是冷调纸张与墨，不是暖色奶油风（刻意避开 AI 常见的 cream+terracotta、黑底荧光色、报纸细线三种套路）。

### 3.2 色彩（4–6 个命名色）

| Token | 色值 | 用途 |
|---|---|---|
| `--ink` | #1C2127 | 主文字、标题 |
| `--paper` | #F6F7F9 | 全局底色（冷灰白） |
| `--sheet` | #FFFFFF | 内容卡片/纸面 |
| `--seal`（印章朱） | #BE3A2B | 仅用于：待人工确认、外发动作区、风控暂停。全应用稀有 |
| `--evidence`（松烟绿） | #2E7D5B | 证据充分、通过、confirmed |
| `--ai`（靛蓝） | #33567F | AI 标签、模型产出标记、链接 |
| `--rule`（发丝线） | #E1E5EA | 分隔线、卡片边 |
| `--ink-2` | #5C6672 | 次要文字 |
| `--hold`（待办黄） | #9A6A00 | 草稿/待确认的描边与小标签 |

语义红绿灯：通过=evidence 绿；待确认=hold 黄（草稿）/ seal 朱（必须行动）；错误/风控=#B3261E。**评分不使用红绿配色**（避免「分数高=好」的暗示，分数旁边必须是 Fit/Gap/Risk 文字）。

### 3.3 字体

- **UI / 正文（中文主）**：IBM Plex Sans SC + 系统回退（PingFang SC / Microsoft YaHei）。选 Plex 而非 Inter：它带一点工程仪器感，中西文混排稳。
- **数据 / 编码 / 状态标签**：IBM Plex Mono。计数、ID、时间戳、节流毫秒数、rule_id、模型名——全部等宽，表格列自然对齐，也强化「终端」气质。
- **长文阅读（JD 原文、聊天）**：同上无衬线，行高 1.75，栏宽 68ch；不使用衬线字体（屏幕长读宋体反而累）。
- 标题仅用字重与灰度分级（600/500/400），不引入第二种展示字体——克制是这个产品的性格。

### 3.4 间距与形状

- 8px 栅格；卡片圆角 6px，按钮 4px；**细线 1px 为主，不用阴影堆叠**，层级靠留白和底色区分。
- 信息密度基准：表格行高 36px，卡片内边距 16px；提供「紧凑模式」开关（行高 30px）。
- 动效：仅状态变更反馈（120–160ms，淡入/高度），尊重 `prefers-reduced-motion`；无页面转场动画、无背景动效。

### 3.5 Signature（记忆点）：左侧「漏斗导航 + 待办计数」+ 证据点

两个互相咬合的独有元素：

1. **漏斗导航**：左栏按真实流程七级竖排，级间细线连接，每级右侧等宽数字（待办/总数）。数字非零且需要你处理时，该级名前出现一枚小朱点。它不是装饰编号——它就是业务流程本身。
2. **证据点（Evidence dot）**：出现在每条 Claim、每个 JD 标签、每个评分依据前：`● 有证据`（绿）/ `◐ 部分证据`（黄）/ `○ 无证据，不可发布`（灰空心）。Claim 文本悬停浮出证据出处卡片。同一符号系统贯穿简历、招呼语、Guard 清单、复盘。

## 4. 全局框架

### 4.1 桌面三栏（≥1280px 主用场景）

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 顶栏  ●扩展已连接 BOSS直聘  │  节流 1800ms±20% 并发1  │  AI: 本地/云端   │ 备份 ✔ │
├───────────┬────────────────────────────────────────────┬─────────────────┤
│ 漏斗导航   │  主内容区（当前案卷）                        │  上下文栏(可选)  │
│  220px    │                                            │  320px          │
│           │                                            │                 │
│ ▸ 采集  3 │                                            │  证据 / Guard / │
│ ▸ 筛选 12 │                                            │  时间线，       │
│ ▸ 候选  4●│                                            │  随页面切换     │
│ ▸ 投包  2 │                                            │                 │
│ ▸ 待确认 5●│                                           │                 │
│ ▸ 复盘    │                                            │                 │
│ ───────   │                                            │                 │
│ 模板中心   │                                            │                 │
│ 知识库    │                                            │                 │
│ 设置      │                                            │                 │
└───────────┴────────────────────────────────────────────┴─────────────────┘
```

- **顶栏是系统状态，不是品牌位**：扩展连接灯（绿/黄/灰，点击进配对页）、风控参数只读展示（设置里才能改，且有下限保护）、AI Provider 状态、上次备份时间。风控暂停时顶栏整条转 `#B3261E` 并显示「采集已暂停：<风控词>，需手动恢复」。
- **右栏是页面定义的「第二视角」**：岗位详情里是证据与匹配依据，投递包里是 Guard 清单，事件台里是状态时间线。可折叠记忆状态。
- 无全局弹窗营销；确认动作使用行内/抽屉确认，不可逆动作（清除聊天数据）才用模态框并要求输入确认词。

### 4.2 AI 草稿态 vs 已确认态（贯穿全站的组件语言）

```text
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─┐    ┌──────────────────────┐
│ ◐ AI 草稿 · gpt-xx ·  │    │ ● 已确认 09-12 14:30 │
│   14:28  [证据 2]     │    │ 5 年 Python 后端经验  │
│ 5 年 Python 后端经验   │    │ 来源：工作经历 A      │
│              [拒绝] [确认] │    └──────────────────────┘
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─┘
   虚线卡 + hold 黄描边         实线卡 + 正常底
```

- 任何 AI 字段未经确认**不进事实层、不进导出、不投影状态**（对应不变量与 `review_status=draft`）。
- AI 修改过的字段显示「你改过 AI 的措辞」的小标记，可对比 diff（AI 原文 / 你的版本）。

### 4.3 外发动作区（统一组件，全站唯一形状）

出现在投递包页与在线填充页，朱色细边框包围，白底，措辞精确：

```text
┌─ 对外动作（都由你本人完成，系统不会自动发送）──────────────┐
│  [ 复制招呼语变体 A ]   [ 填充到网页·先预览 ]   [ 我已发送，标记 ] │
│  红线字段（公司/职位/起止时间/学历）永不自动填入，需手填。      │
└──────────────────────────────────────────────────┘
```

「标记已发送」只记录状态（人工回执），不触发任何站点操作。

## 5. 逐页设计

### 5.0 首页：今日案头（打开即落点，替代传统 Dashboard）

- 单一职责：回答「今天要处理什么」。按优先级列四组待办，点击直达：
  1. **待确认事件**（5）——聊天草稿不确认就不进漏斗，最高优先；
  2. **待做候选决策**（4）——筛完但你没看的岗位；
  3. **待完成投递包**（2）；4. 采集中/风控提示。
- 顶部一条极简周漏斗：`captured 38 → pass 12 → 候选 4 → 已招呼 2 → 回复 1 → 约面 0`，等宽数字，点数字跳到对应过滤视图。
- 空态（没有待办时）：「没有待你确认的事项。去[采集新岗位]或[看看复盘]。」——不庆祝、不插画。

```text
今天，9月15日 周二            本周漏斗  38→12→4→2→1→0
─────────────────────────────────────────────────
● 待确认聊天事件      5 条 >      （公司·时间·分类建议）
● 待决策候选          4 个 >
  待完成投递包        2 个 >
  扩展状态：已连接 · 上次采集 09-14 21:03 · 无风控信号
```

### 5.1 采集中心

- 页签：扩展配对与状态 / 批次列表。
- 配对页：二维码或配对码输入、8788 连接状态、Origin 与 loopback 只读说明（让你知道安全边界是实装的）。
- 批次列表：每批一行——时间、条数、阶段（list/detail）、节流设置快照、状态（running/aborted/halted/completed）、风控提示。
- running 批次唯一操作：**[ 暂停采集 ]**（abort）；没有「加速」「自动翻页」控件——`auto_next_page` 不出现在 UI。
- halted（风控）行：整条黄/红底，显示命中风控词与「请人工确认站点情况后恢复」，恢复按钮需二次确认。

### 5.2 岗位池与筛选（高频页，信息密度最高）

三栏：左 Filter Set 列表与版本 | 中岗位表格 | 右淘汰原因/规则命中详情。

```text
Filter Sets          │ 岗位池（set: 上海后端 v3）          │ 选中岗位：
● 上海后端 v3 (在用)  │ ┌───────────────────────────────┐ │ ○ 某科技·Python
  校招宽松 v1         │ │公司 职位 薪资解析 活跃 规则结果  │ │   淘汰原因：
  + 新建（八组规则）   │ │xx  Python 25-40K·月  2时前 通过│ │   ✗ 薪资低于下限
─────────────────────│ │yy  Java   18-22K·月  3天前 淘汰│ │     期望 25K
 [运行筛选] 不调 AI   │ │...                             │ │     解析 18-22K
 每条淘汰可定位可捞回  │ └───────────────────────────────┘ │   [ 捞回 ]
                     │ 计数：通过 12 / 淘汰 26（可点）     │ 证据：详情原文
```

- 表格支持：列排序、按规则结果过滤、薪资口径列始终带单位标签（月K/月元/日/时/年/未知，等宽小字）。
- 淘汰不是终态：行内「捞回」，必须填一句捞回理由（留痕）；薪资「未知」单列，不参与薪资硬淘汰。
- Stage-0 运行时显示「纯规则 · 0 次 AI 调用」标识（这是产品承诺，UI 上可验证）。

### 5.3 候选区（唯一投递入口，决策页）

- 左：候选卡片流（公司/职位/薪资/活跃度/匹配摘要三行 Fit/Gap/Risk）。
- 中：**JD 分区阅读**——Requirements 结构化标签（每个标签带来源页码/原文句，可展开回原文）+ 原文切换；AI 提取的标签是草稿态，你可逐条确认/修正（修订产生新版本）。
- 右：匹配依据与 ATS 建议——每个评分项挂证据点；建议文案用陈述句（「该岗位 6/9 必须项有直接证据，Gap 在 Kubernetes」），**不出现分数大字、不出现推荐星**；底部只有两个动作：[ 移出候选 ] / [ 制作投递包 ]。
- 重复候选冲突（SHORTLIST_CONFLICT）行内说明已存在的 Application。

### 5.4 投递包（三形态 + 招呼语 + Guard）

- 顶部：绑定信息（Resume Version 快照、Match Result、被选招呼语变体——都不可变，重优化=新版本）。
- 主体三栏标签：**ATS 单栏 / Showcase / 在线表单**，同一份 Claim 集合的三种呈现；编辑器分流为「内容编辑（触发 Claim 重校验）」与「排版编辑（不动事实）」。
- 每条 Claim 前证据点；`○ 无证据`的 Claim 在右栏 Guard 清单置顶，导出按钮在 Guard 有阻断项时禁用并说明缺什么。
- 招呼语：默认 3 条变体 A/B/C 并列，逐句可点开溯源；选中一个才点亮外发动作区；显示「被选变体会被记录」。
- 导出：PDF / PNG / HTML / DOCX / MD；导出后回读校验失败给 TEMPLATE_DRIFT 明确说明（哪个字段不一致），不用模糊报错。

### 5.5 事件确认台（聊天回采，隐私敏感页）

```text
左：会话列表（公司·最后消息时间·草稿数）
中：消息流 + 分类草稿
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
│ ◐ AI 草稿分类：约面？  置信度 0.82          │
│ HR：「方便下周三来面试吗」                  │
│ 时间：…        [拒绝][改为：拒绝/其他] [确认约面] │
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
右：该 Application 状态投影时间线（确认后才出现新节点）
```

- 页面顶部常驻隐私条：「聊天原文仅存本机、加密；不进入任何第三方请求。[按会话清除]」。
- 未确认时右侧时间线**纹丝不动**——用 UI 证明草稿不投影；确认后节点以 150ms 淡入。
- 分类错误成本高，按钮顺序按后果排列：中性动作在左，状态推进在右，危险（标记拒绝）需二次确认。

### 5.6 模板中心

- **默认网格库**：模块×布局×风格组合以卡片网格浏览（缩略图 + 标签 + 许可标识）；3D 画廊是设置里的开关，默认关，不占主导航。
- DOCX 导入批：上传→八步管线进度（断点续跑）→报告：A/B/C 保真分级 + 逐条失败原因；C 级模板上有显式警示带，不静默可用。
- A4 编辑器：纸张居中超大留白，工具条靠边；事实字段以插槽 chip 显示（来自知识库），不能在模板里写死事实文本（写了保存即拒，模板红线）。

### 5.7 复盘与漏斗

- 漏斗看板：七级（captured→screened_pass→shortlisted→greeted→replied→interview_scheduled→offered）桑基/条形二选一（建议条形，数字精确优先），每级可下钻到岗位明细，保证与 SQL 对账一致。
- 单岗复盘：终态岗位才有，版本不可变，顶部显示版本号与生成时间；引用可一路跳到聊天事件（本机内）。
- 策略建议：列表 + 状态（proposed/approved/applied/archived）。approved 行明确标注「不会自动改任何参数；应用需你手动操作并标记」。

### 5.8 知识库 / 5.9 设置

- 知识库：四类来源（Profile/work 连接器、career-kb 导出、旧简历、JD 引导补录）→ 抽取项全部草稿态待确认；事实/二开/学习参考三色分类；Evidence 浏览带证据点。
- 设置：模型与密钥（密钥只显示是否已配置，掩码，不明文回显）；节流参数（下限保护：<1800 输入被拒并说明原因）；备份与数据清除（清除按会话，有确认词模态）；3D 画廊开关。

## 6. 核心组件清单（设计系统第一批）

| 组件 | 说明 |
|---|---|
| `<FunnelNav>` | 漏斗导航 + 等宽计数 + 朱点待办 |
| `<EvidenceDot level>` | ●/◐/○ 证据点，统一三态 |
| `<AiDraftCard>` | 虚线草稿卡：模型标签、时间、证据数、确认/拒绝 |
| `<ConfirmedCard>` | 实线已确认卡：确认时间、来源 |
| `<OutreachActionBar>` | 外发动作区（复制/填充预览/标记已发送），全站唯一 |
| `<GuardList>` | 阻断/警告清单，阻断时禁用主按钮 |
| `<RuleHitDetail>` | rule_id + 字段 + 期望值 + 实际值 + 原文引用 |
| `<RiskBanner>` | 风控暂停顶带/行带 |
| `<StatusTimeline>` | Application 状态时间线（只认 confirmed） |
| `<ClaimChip>` | 事实插槽（模板编辑器用，不可写死文本） |
| `<EmptyState>` | 空态：一句话 + 一个主动作链接 |
| `<DiffView>` | AI 原文 vs 本人修订 |
| 数据表格 | 等宽数字列、可排序过滤、行内捞回/抽屉 |
| Toast | 与按钮同名（「已标记发送」对应「标记已发送」），错误说清怎么修 |

## 7. 文案与语气

- 说用户控制的东西，不说系统构造：「待你确认的消息」，不说「review pending events」。
- 按钮即结果：[ 复制招呼语 ] → toast「已复制，去 BOSS 粘贴后手动发送」。
- 错误不道歉、不含糊：「解析失败：该 DOCX 使用了文本框排版，当前导入器读不到内容（C 级）。可改用 PDF 或手动建模板。」
- 空态是行动邀请：候选区空时——「还没有候选岗位。先去[岗位池]完成筛选，或从[淘汰列表]捞回。」
- 不替用户下职业判断：禁词「最佳匹配」「推荐投递」「保证」；用「证据更充分」「Gap 在…」。

## 8. 响应式与可达性

- **桌面优先**（1280–1920 主用）；≥1024 三栏，768–1024 右栏转抽屉，<768 只保留只读视图（漏斗/看板/详情，不做编辑与外发动作）。
- 键盘：所有确认/拒绝/捞回可 Tab 到达；焦点环用 `--ai` 蓝 2px；色弱友好：证据点三态同时靠形状（实心/半圆/空心）不只靠颜色。
- 明暗主题：v1 只做浅色（案头纸感需要），深色留 token 层伏笔，不承诺。

## 9. 技术映射（不展开实现）

- React 18 + Vite + TS；TanStack Query 管 SSE/WS 状态（采集进度、事件草稿用 WS 事件增量更新缓存）；RHF + Zod，**Zod 类型由 contracts-ts 生成，不手写**。
- 路由即页面地图 9 区；权限模型简单：只有「本人」，但 UI 仍区分只读/可操作态（例如未配对扩展时采集页全只读）。
- 所有枚举、错误码（SHORTLIST_CONFLICT / TEMPLATE_DRIFT / skipped_redline 等）从契约取，前端不自造。
