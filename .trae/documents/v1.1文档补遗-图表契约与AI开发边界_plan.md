# v1.1 文档补遗：图表补齐 + 开发契约骨架 + AI 开发边界 — 实施计划

## 一、仓库调研结论（差距评估）

### 1. 现有资产
- 总体方案 1 篇 + architecture/ 22 篇 + README，共 24 个文档，v1.1 口径一致。
- 已有图 13 张 Mermaid：总体 7（系统上下文、领域图、Compose 拓扑、3 个时序、总 ER）、01 领域流、02 组件、03 主流程、07 证据管线、12 ER、17 部署拓扑。
- 契约现状：21 篇有 WS 命令/事件表与 chat.event JSON 示例；13 篇有接口总表 + 错误码列表（**无 HTTP 映射**）；12 篇是字段清单（**无 DDL/类型/可空/外键**）；15 篇有 DSL 约束（**无 JSON Schema**）；08 篇有规则组表（**rule_json 无 Schema**）。
- 仓库根无任何代码、无 AGENTS.md、无 contracts/。

### 2. 「能否直接开发」结论
- **P0（文档/契约）、P1（骨架+扩展重写）的架构依据已足够**，但开工前缺三类东西：
  1. **图缺口**：状态机、规则管线、页面动线、降级路径等只在散文里，开发各自理解易跑偏；
  2. **机器可读契约**：字段清单无法做 codegen/契约测试/前后端并行，属 P0 定义的「协议契约可被两端同时引用」未闭环；
  3. **开发基线**：无仓库结构、技术栈版本、配置清单、本地启动/测试规程、每阶段 Definition of Ready。
- **AI 协作无边界文件**：红线散落在 ADR/20/21 各篇，AI 编程代理进仓库后不会自动读到，存在生成自动发送 handler、放宽节流、误引商业库等风险。

### 3. 已确认决策（用户选择）
- 契约深度：**文档 + 契约骨架文件**（contracts/ 下 WS JSON Schema、OpenAPI 骨架、DDL 草案、DSL/Filter Schema，约 10 个文件）。
- AI 边界：**新增第 24 篇 + 仓库根 AGENTS.md**（代理自动读取，硬红线精简版）。
- 补图：**11 张全补**，嵌入所属专题，不新建图册文档。
